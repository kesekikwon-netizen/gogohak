## 확인한 사실
- 근거로 쓴 실제 화면: 홈(2026-10-11 00:0x 캡처), 지도(2026-10-10 사용자 스크린샷 image.png, 3440×1440 · 150 %), 도면(시험 save_open_monitor가 가상 화면 2293×912에서 찍은 그림, 자료 없음), 창 3개(계정 · 검수·제출 · 새 조사, 같은 시험).
- 기준서와 어긋난 곳 20곳을 찾았다. 큰 줄기는 「한 장」 원칙(§1.1)을 아직 어기는 둥근 상자·카드(홈 전체, 지도의 세 판, 도면 오른쪽 판 상자 셋, 최근 조사 표), 「켜짐의 세 모습」(§1.4)이 섞인 곳(그리기 줄의 고른 도구가 귀리색, 탭이 화면마다 다름), 창의 단추·입력칸 높이(단추 약 50 px, 입력칸 약 40 px; 기준 32), 알림 창 두 가지(KaUserError 41곳 + 기본 경고창 29곳).
- 바탕 코드: 홈 틀·표 상자 `data/theme/ka-hgis.qss` 59·77행, 단추 높이 142행(`QPushButton min-height 34`), 입력칸 113·124행, 띠 글자 `KaLayerSectionDelegate.cpp` 91행, 용지 설정 잠금 `KaDrawingStudio.cpp` 446행, 범례 중심 검사 2726행, 오른쪽 판 스크롤 `KaInspectorPanel.cpp` 73·93행.
- 이미 기준대로라 손대지 않는 것: 새 조사 창의 경도 눈금자·「추천」, 홈 상단(작은 Strata + 두 테두리 단추), 작업 순서의 흙색 점 + 「다음」, 탭 줄 오른쪽 「● 저장 안 됨」, 오른쪽 판 아래 「배경 지도」 붙은 세 칸, 지도의 「▲ 도북」·축척 막대, 도면 아래 도구 줄 하나.
- 저장소의 「Design System」 아티팩트는 비어 있어 쓰지 않았다. 캔버스는 기준서의 토큰(§2)으로 직접 그렸다.

## 문제
- 화면마다 같은 뜻이 다른 모양이다(탭, 켜진 도구, 판 틀, 알림 창). 현장에서 「이건 눌리는 건가, 켜진 건가」가 모양만으로 안 읽힌다.
- 홈 표제란의 단추 칸 아래 선이 13 px 어긋나고, 폴더가 「C: › Users › …survey-verify」로 줄어 읽기 어렵다.
- 창의 단추·입력칸이 커서 창이 길어지고, 검수·제출 창의 「오류 / 건」이 두 줄로 깨진다.

## 바라는 결과
- 캔버스 「계획표」 판의 20항목(H1~H6 홈, M1~M8 지도, L1~L5 도면, D1~D3 창, R1 튼튼함)이 「바꿀 것」 판 그대로 앱에 들어간다. 기능은 더하지 않고, 화면의 선·상자·높이·글자·색만 바꾼다.
- 차례: 1차 작은 것 12(H1~H6 · M2~M7, 각 S) → 2차 판·창 공통(M1 · L1 · L2 · L3 · L5 · D1) → 3차 표시 오류(D2 · L4 · R1 · M8) → 4차 알림 한 틀(D3, 세 묶음). 항목마다 커밋 하나.

## 영향받는 곳
- 홈(KaStartPage*), 지도 판·탭·상태줄(MainWindowChrome, KaStatusBar, KaInspectorPanel, KaLayerSectionDelegate, 그리기 줄), 도면(KaDrawingStudio 오른쪽·왼쪽 판, 용지, 범례 배치), 창(ka-hgis.qss 공통 단추·입력칸, KaSubmitDialog, KaUserError 호출 29곳), 파일함(KaFileBrowserPanel).

## 지켜야 할 것
- 기준서 §7 금지 목록: 리본의 크기·순서·그림, 10 px 레이어 글자, 그리기 줄 순서, 상태줄 내용은 그대로. 어두운 화면 없음. 지도·도면 용지·제출 PDF의 그림은 바꾸지 않는다.
- 기능 추가·삭제 없음. 예외는 M8의 SD 카드 단추(사용자 요청 R15)뿐이다.
- 충돌 규칙: 캔버스를 다시 그리거나 refresh 하는 변경 없음(모두 Qt 위젯·QSS).
- 줄 수 한도: 핫스팟(KaDrawingStudio·MainWindow)은 연결 몇 줄만, 새 코드는 새 파일(KaPaperDialog, LegendPlacement 등).

## 이번에 하지 않는 것
- 새 기능(유구 등록부 등), 어두운 화면, 목업의 새 표시(시대 띠 등은 이미 있음), 1280 노트북의 리본 아이콘 크기(§7 리본 불변).
- 「추가/속성」 나누기(§4.4가 한 구역으로 정함).

4. 네 차례를 모두 할까요, 1·2차만 먼저 할까요? — 추천: 모두, 차례대로. 1차 12개는 각각 한 커밋이라 하루 안에 끝난다.

## 확인 방법
- 항목마다 바꾸기 전에 실패하는 화면 시험(크기·색·테두리)을 넣고 바꾼 뒤 통과를 본다. 기존 기댓값을 바꾸면 커밋에 「시험 변경:」.
- 항목이 끝날 때마다 run-strata로 실제 화면을 찍어 캔버스의 「바꿀 것」과 나란히 둔다. 2차 D1은 창이 열리는 묶음(save_open_monitor · theme_render · plate_render)을 함께 돌린다.
- 1차가 끝나면 홈·지도 화면을, 2차가 끝나면 도면·창을 찍어 보여 드린다.
