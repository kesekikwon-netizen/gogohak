ARCHAEO STUDIO는 WordCraft 워드프로세서 안에 제미나이 학술 스튜디오를 붙인 고고학 『Ⅳ. 고찰』·학술논문 작성 앱입니다. 왼쪽 패널에서 요청과 자료를 넣고 실행하면, 오른쪽 A4 용지 위에 본문·표·쪽 아래 각주·참고문헌이 실시간으로 쓰이고 그 자리에서 고칩니다. 화면은 Trowel 3.0의 Quiet Plate를 그대로 따릅니다: 따뜻한 종이색 바탕, 먹색 글자, 토기 흙색 강조 하나.

## 원칙

1. **없는 자료는 없는 대로.** 비워 둔 자료 칸은 오류가 아닙니다. 빈칸을 붉게 칠하거나 채우라고 재촉하지 않고, 진행 기록에 「연대분석 자료가 비어 있어 연대 수치는 쓰지 않습니다」처럼 어떻게 다뤘는지 남깁니다.
2. **쓰는 곳은 A4 한 장.** 결과는 채팅 말풍선이 아니라 바로 고칠 수 있는 .docx 용지 위에 나타납니다. 작성 중에도 사용자가 고칠 수 있습니다.
3. **흙색 단추는 하나.** 한 화면에서 눌러야 할 흙색(`clay`) 단추는 고른 문서 종류의 실행 단추뿐입니다.
4. **지금 일은 한 줄로.** 수집과 작성의 진행은 A4 위 `CollectStrip` 한 줄과 상태줄 한 문장으로, 자세한 일은 진행 기록에.
5. **PDF는 부를 때만.** 모든 작업과 저장은 .docx로 하고, PDF는 「PDF로 내보내기」를 눌렀을 때만 만듭니다.
6. **선이 칸을 나누고, 그림자는 떠 있는 것(용지, 창, 메뉴)에만.**

## 말투와 글

- 고고학 연구자와 조사원이 바로 아는 쉬운 한국어만 씁니다. 화면에 쓰지 않는 말: 프롬프트, 토큰, 페이로드, 벡터, RAG, MCP, CDP, 헤드리스. 대신 쓰는 말: 「요청」, 「1차 가공」, 「내 보고서·조사 자료」, 「연대분석·보유 자료」, 「파일 불러오기」, 「디비피아 로그인」, 「실행」, 「진행 기록」.
- 문장은 「~합니다」로 끝냅니다. 안내는 지금 할 일 한 문장: 「요청과 자료를 넣고 실행하세요. 비워 둔 자료는 빼고 씁니다.」
- 단추는 하는 일을 짧게: 「발굴조사보고서 고찰 실행」, 「잠시 멈춤」, 「그만두기」, 「닫고 계속하기」, 「내보내기」. 「확인」 「취소」 「OK」는 쓰지 않습니다.
- 진행 기록은 한 일을 한 문장으로, 무엇을·몇 건: 「DBpia에서 관련 논문 12건을 찾았습니다」, 「논문 1건은 원문을 열 수 없어 빼고 썼습니다」.
- 고정 안내 문구 둘은 바꾸지 않습니다.
  - 요청 칸 아래: 「입력하신 요청은 고고학 학술 양식에 맞춰 1차 가공되어 전달됩니다.」
  - 연대분석 칸 아래: 「보유하지 않은 자료는 비워 두세요. 없는 자료는 제외하고 입력된 자료만으로 결과가 작성됩니다.」
- 이모지와 느낌표를 쓰지 않습니다. 아이콘은 `Icon`으로.
- 숫자와 단위: 길이 m·㎝, 넓이 ㎡, 쪽 「45~48쪽」, 시대 「원삼국~백제 한성기」(물결표). 각주 번호는 `1)`.

## 색

- 바탕: 앱 바탕 `bg`(리본, 스튜디오 패널, 상태줄, 수집 띠), 입력칸·상자 `input`, 기본 단추와 안내 상자 `tab`, A4 주변 `canvas`, 용지 `page`.
- 선: 칸 경계 `line`(1px), 상자 안 옅은 나눔 `line-soft`, 컨트롤 테두리 `line-strong`.
- 글자: `ink`, 보조 `ink-muted`. `ink-faint`는 메뉴 단축키에만, `ink-disabled`는 누를 수 없는 것과 입력칸 예시 글에만. 아이콘은 `icon`.
- 고른 것은 `oat`(문서 종류 칸, 켜 둔 스튜디오 타일, 1차 가공 태그). 포인터를 올린 것은 `hover`.
- 흙색 `clay`: 고른 실행 단추, 문서 안 작성 커서, 입력칸 초점 테두리. clay 바탕 위 글자는 `on-clay`, 흙색 글자는 `clay-deep`.
- DBpia·학술 자료는 황동 `brass`(점, 테두리, 열쇠 아이콘). 글자는 `ink`를 `brass-soft` 위에 둡니다.
- 작성 진행은 세이지 `progress`, 끝나면 `ok`. 확인할 일은 `warn`, 오류는 `bad`. 색만으로 알리지 않고 늘 낱말을 붙입니다.
- 창 뒤를 덮을 때는 `scrim`.
- 어두운 테마에서도 `page`는 흰 종이, `page-ink`는 먹색입니다.

## 글자

- 화면 글자는 `sans`(Noto Sans KR, 없으면 맑은 고딕). 줄 높이 1.3, 굵기는 400과 600만. 크기는 정해진 단계만: `ui-title` 13.5 · `ui-body` 13 · `ui-row` 12.5 · `ui-control` 12 · `ui-chip` 11.5 · `ui-caption` 11 · `ui-micro` 10.5.
- 시각·쪽·글자 수·퍼센트·파일 크기는 `mono`(IBM Plex Mono): `num-status`, `num-small`.
- A4 문서는 `serif`(바탕, 없으면 Noto Serif KR): `doc-title` 18pt · `doc-chapter` 16pt · `doc-section` 12pt · `doc-body` 10pt(줄 간격 170%) · `doc-table`·`doc-abstract`·`doc-reference` 9pt · `doc-footnote` 8pt. **이 크기는 확정 전 제안값입니다.**
- 한글·한자·고고학 기호(Ⅰ Ⅱ, ㎝, ①)가 □로 깨지지 않도록 글꼴 목록 끝에 늘 맑은 고딕과 시스템 글꼴을 둡니다.

## 크기·간격·모서리

- 한 화면 1440×880 기준: 제목줄 `size-title-bar` 32 · 리본 `size-ribbon` 86 · 몸통 · 상태줄 `size-status-bar` 28.
- 몸통 왼쪽 스튜디오 패널 `size-studio-panel`(392, 끌어서 `size-studio-panel-min` 360 ~ `size-studio-panel-max` 420), 나머지 70~75%가 A4 편집 화면. 리본 「스튜디오」 타일로 패널을 접으면 A4가 화면 전체를 씁니다.
- 간격은 `space-2`~`space-16`(이름의 숫자 = px). 패널 좌우 `space-16`, 단계 위아래 `space-12`, 단계 안 줄 사이 `space-8`.
- 모서리: 단추·입력칸·상자 `radius-7`, 찾기 칸·메뉴 `radius-8`, 리본 타일 `radius-9`, 창·대화상자 `radius-10`, 태그·칩·진행 막대 `radius-full`.

## 화면 구성

1. **제목줄**: 「문서 이름.docx - ARCHAEO STUDIO」.
2. **리본**(`StudioRibbon`): 파일(새 문서 · 열기 · 저장) · 홈·서식(글자) · 삽입(표 · 도면 · 각주) · 스튜디오(패널 열고 닫기) · 내보내기(PDF 변환), 오른쪽 끝 명령 찾기. 리본 타일에는 흙색을 쓰지 않습니다.
3. **스튜디오 패널**: 단계 여섯(`StudioStep`). 1~4는 스크롤되고 5·6은 아래에 붙어 늘 보입니다.
   1. 문서 종류 — `Segmented` lg: 발굴조사보고서 고찰 / 논문. 작성 중에는 잠김.
   2. 요청 — `PromptField`: 요청 칸, 1차 가공 안내, 가공된 요청 보기.
   3. 내 보고서·조사 자료 — `SourceInput`: 붙여 넣기 + 파일 불러오기(.docx .pdf .txt .md .csv).
   4. 연대분석·보유 자료 — `SourceInput` optional, 「선택」 태그, 비어 있으면 「비워 둠」.
   5. 실행 — `RunPanel`: 실행 단추 둘, 작성 중 잠시 멈춤·그만두기, 디비피아 로그인과 상태, PDF로 내보내기.
   6. 진행 기록 — `LogPanel`: 진행 막대와 한 줄 기록.
4. **A4 편집 화면**: `canvas` 위에 수집 띠(`CollectStrip`), 그 아래 `DocPage`.
5. **상태줄**(`StatusBar`): 지금 일 한 문장 · 쪽 · 글자 수 · 배율.

상태별 화면은 「화면 시안」 묶음의 다섯 장(실행 전 · 디비피아 로그인 · 작성 중 · 작성 끝 · 논문)을 따릅니다.

## A4 문서 양식

- 용지 `size-a4-w`×`size-a4-h`(210×297mm), 흰 `page`에 `page-ink`, 그림자 `shadow-page`. 편집 화면에서는 90%로 보여 줍니다.
- **발굴조사보고서 고찰**: 장 제목 「Ⅳ. 고  찰」 가운데 → 절 제목 「1. 유구 구조와 편년적 위치」 → 본문(첫 줄 1자 들여쓰기, 양쪽 맞춤) → 표 → 문서 끝 【참고문헌】.
- **논문**: 제목(가운데) → 저자(소속) → 국문초록·주제어(가는 선 사이) → Ⅰ. 머리말 ~ Ⅴ. 맺음말 → 【참고문헌】.
- 본문 인용 번호는 위첨자 `1)`, `2)`(`FootnoteRef`).
- 쪽 아래 각주: `1) 저자명, 발행연도, 「논문 제목」, 『학술지명』 권호, 발행기관, 인용쪽(00~00쪽).` 본문 너비 1/3 길이의 가는 선 아래.
- 【참고문헌】: `저자명, 발행연도, 「논문 제목」, 『학술지명』 권호, 발행기관.` 둘째 줄부터 내어쓰기.
- 표(`DocTable`): 위에 「표 1. …」 제목, 머리 칸 굵게, 위아래 테두리 굵게.
- 작성 중인 자리에는 흙색 커서(`DocPara`의 `live`)만 둡니다. 실행 전 빈 용지에는 「실행하면 이 자리에 『Ⅳ. 고찰』이 작성됩니다. 직접 써 넣으셔도 됩니다.」

## 상태 표시

| 상태 | 모양 |
| --- | --- |
| 실행 전 | 수집 띠에 빈 황동 고리 「실행 전」, 진행 기록 빈 문구, 고른 실행 단추만 흙색 |
| 작성 중 | 실행 단추 「작성 중…」(누를 수 없음), 잠시 멈춤·그만두기 등장, 문서 종류 잠김, 세이지 진행 막대 |
| 작성 끝 | 실행 단계에 「작성 끝 · 시각」 ok 태그, 진행 막대 ok, 수집 띠에 각주·참고문헌 수, 「PDF로 내보내기」 한 단계 올라옴 |
| 디비피아 | 태그 「로그인 필요」(회색) / 「로그인됨」(황동) |
| 확인할 일 | 진행 기록 `warn` 줄 |
| 오류 | 진행 기록 `bad` 줄, 상태줄 붉은 글자 |

## 디비피아 로그인 창

- 「디비피아 로그인」을 누르면 앱 위에 `DbpiaWindow`가 뜨고 뒤는 `scrim`으로 덮입니다.
- 앱은 창의 틀(제목, 주소 줄, 상태 태그, 닫기)만 그리고, 안쪽에는 디비피아 사이트가 그대로 열립니다. 디비피아 로그인 화면을 앱이 따로 그리지 않습니다.

## 아이콘

- 선 아이콘 한 벌: 24 칸, 선 1.6, 둥근 이음, `currentColor`(Trowel 3.0과 같은 규칙). 부품 안에서는 `Icon`으로 그리고, `Icons` 묶음 파일은 그림으로 쓸 때만.
- 쓰는 아이콘: `new` `open` `save` `text` `table` `img` `footnote` `panel` `export` `search` `run` `pause` `stop` `key`.
- 앱 마크는 아직 없습니다. 이름 「ARCHAEO STUDIO」를 글자로만 씁니다.

## 부품 쓰기

- `components/bundle.js`가 `window.ArchaeoStudio`를 만듭니다. React 18(`components/lib/`)을 먼저 올리고, `tokens.css`와 `components/bundle.css`를 함께 넣습니다.
- 부품은 값을 받아 그리기만 합니다(`value`/`onChange`, 없으면 `defaultValue`로 스스로 기억). 수집·작성·저장 같은 동작은 쓰는 쪽이 줍니다.
- 실제 앱(Rust/egui WordCraft)에는 이 묶음을 직접 넣지 않습니다. 토큰 값과 칸 크기를 egui 테마에 옮기고, 부품 미리보기와 화면 시안을 화면 비교 기준으로 씁니다.
